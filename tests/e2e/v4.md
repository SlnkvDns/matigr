# V4 — коррекция и места

24 октября 2026, тот же `matigr-e2e-final` после V3. Через браузер Бета подала по Correct/20 задачи 2, jury-a вручную выбрал и завершил Incorrect. Checking был остановлен при claim: UI принял 202 как ожидание, сохранился тот же request. После старта Checking восстановил назначение без второго Check.

Во время вердикта `check-appeal-publication-crash.mjs` блокировал SQL Sent после настоящего Rabbit confirm и делал SIGKILL Results. Restart восстановил тот же messageId/receipt/publication. Appeals был остановлен; `check-appeals-reordering.mjs withhold` сохранил/временно изъял настоящие Assigned/Completed, дал Applied первым закрыть процесс. `release` вернул все сообщения и дубли с новыми messageId; Closed/version не регрессировали.

Браузер посетителя ушёл на about:blank до вердикта и пропустил уведомление. Возврат после restart показал GET-снимок: Альфа 10/место1, Гамма10/место1, Бета0/место2. Баллы Беты заменены, не добавлены. Командный экран показывает Incorrect/0/version2, Closed указывает на новую публикацию, неизменная база указывает на прежнюю. Ссылка с version2 вновь показывает существующую Closed без кнопки подачи; настоящий новый HTTP key получает AlreadyAppealed.

`check-appeals-final-state.mjs` подтвердил два исторических publication у изменённого результата, разные base/final IDs, один Appeal Check и неизменную квоту. Десять последовательных анонимных snapshot GET: p50 10.7ms, max55.3ms на этом локальном наборе. Это smoke для трёх команд/двух задач, не нагрузочный порог и не SLO Q10. Транзакционная согласованность snapshot проверена PostgreSQL reader/writer barrier tests RES-IT-03/04; масштаб и эксплуатационные требования остаются ограничением Q10.
