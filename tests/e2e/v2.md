# V2 — отказ и окончательный вердикт старшего

CHK-E2E-02 продолжает общий V1 на том же изолированном Compose. В браузере обычный жюри берёт следующую подготовленную проверку. Старший берёт другую из общей очереди и остаётся занят. Обычный передаёт свою старшему: UI подтверждает очередь и освобождение. Старший переключает очередь на старшую: переданная работа видна, прежнее назначение сохраняется, взять вторую нельзя. После завершения своей работы старший берёт переданную.

Закрыть вкладку старшего с активным назначением; открыть новую и снова выбрать того же субъекта. UI должен восстановить ту же задачу/команду и статус «Окончательный вердикт старшего», без команды повторного отказа. Завершить бинарным вердиктом. Сверить историю Checking, actual assignment/reviewer/escalation в публикации Results и публичную таблицу. Полномочия для апелляции проверяются отдельно в APL-E2E-01.

24 октября 2026 сценарий выполнен браузером на `matigr-remaining-faults`: жюри передал Гамма/задача 1, пока старший проверял Гамма/задача 2. Обычный сразу свободен. В старшей очереди работа сохранилась, второй захват недоступен. Старший завершил задачу 2 (Correct 20), взял задачу 1, закрыл вкладку, восстановил её новым входом и завершил (Incorrect 0). Checking содержит один Check/два assignment для переданной работы, origin SeniorEscalation; у задачи 2 один assignment и OrdinaryReview, хотя автор тот же Senior. Results сохранил фактического старшего, assignment и escalationId; данные сверены по ID, обе публикации доступны. Локальный скриншот восстановления: `.local/e2e/v2-resumed-senior.png`.

APL-E2E-01 завершает V2 после реализации подачи: команда Гамма открыла собственный Published Incorrect 0 задачи 1, перешла по серверному resultId/version и нажала подачу. Сервер вернул BaseNotAppealable; UI показал окончательность старшего и заблокировал повтор. В Appeals нет строки по этому tuple, в Checking остаётся один Initial Check. При этом задача 2 того же автора Senior с OrdinaryReview успешно зарегистрирована в предыдущем HTTP admission gate. Запрет основан на decisionOrigin, а не роли человека.
