# Ревизия документации после реализации MVP

26 октября 2026 года, по поручению пользователя проверить и актуализировать оставшуюся документацию. Это изменение статусов и навигации, не новая функция и не повторное согласование MVP.

## Что обновлено

- Корневой/frontend/backend README и fixtures: существующие endpoints, экраны, все три transport adapters, no-op/changed/senior и завершённые приёмки вместо «пока нет/следующая задача»; сохранены ограничения dev/production и безопасного запуска stateful scripts.
- Архитектура, context map, семантика сообщений, implementation contracts и runtime baseline: отделены реализованные T01–T08/local defaults от будущих upstream/retention/SLO. Уточнены принятая Submit/end граница, SSE и фактическое отсутствие закреплённого Playwright runner в npm dependencies.
- Три спецификации: сохранены одобрение от 23 октября и нормативные сценарии; исправлены утверждения об отсутствии реализации/тестов. В plan.md/tasks.md указано завершение первоначального объёма, каждой из 82 задач добавлен статус «Выполнена».
- Authentication/contract README: независимые verifiers, service identity, реальные handlers/consumers и runtime gates описаны как реализованные; проверка формы не выдана за доказательство бизнес-процесса.
- Sites: запись об отсутствии push уточнена как факт на момент публикации, отдельно от последующего GitHub push. Статическая публикация по-прежнему не подключена к backend.

## Журнал без потери истории

Прежний `progress.md` (92 463 байта, 189 длинных строк) сохранён целиком в [архиве MVP](progress-mvp-2026-10-24.md), в том же каталоге, чтобы сохранить относительные ссылки. Сравнение полного текста/байтов перед переносом подтвердило отсутствие потерь. [Текущая сводка](progress.md) занимает около 7 КБ и ссылается на архив/E2E вместо копирования всех промежуточных запусков. Противоречащие текущему итогу исторические статусы в архиве не переписаны.

Архивирование привязано прежде всего к завершению этапа и удобству чтения, а не к каждой задаче. Ориентир 10–15 КБ/150–200 содержательных строк — рекомендация по документации, не бизнес-правило. Нельзя сокращать путём удаления доказательств, дат одобрения или незакрытых вопросов. Новые функции получают собственные план/задачи/журнал, текущий итог остаётся кратким.

- Сохранены 82 task IDs, их этапы и зависимости; граф ацикличен. По сервисам 27/23/32 задачи, все завершены в первоначальном MVP.
- 104 строки приёмки CH-A01–37/RS-A01–31/AP-A01–36 и пользовательские согласования D01–D24 сравнены с состоянием до ревизии: без изменений. Исходная Event Storming диаграмма не редактировалась.

На финальном дереве проверены 34 Markdown-файла; отрицательный smoke временно вводил отсутствующий target/heading в backend README, оба отказа обнаружены, исходные байты восстановлены.
