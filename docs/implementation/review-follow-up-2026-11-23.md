# Исправления по ревью PR №1 от 23 ноября 2026 года

Ревью относится к коммиту `0528d55`. Правила регистрации, назначения перепроверки, публикации и постоянной квоты сохраняются. [Комментарий ревьюера](https://github.com/SlnkvDns/matigr/pull/1#issuecomment-7097038594).

## Функциональность и безопасность

- Deadline запроса Appeals → Results охватывает ожидание заголовков и чтение JSON. Истечение срока приводит к `503 ResultsUnavailable`. Отмена вызывающей стороны передаётся как отмена.
- Миграции, подготовленные данные и выдачу прав выполняют одноразовые контейнеры `*-migrate`. У каждого API отдельная роль PostgreSQL с доступом к своему сервису. У роли API есть чтение, вставка и обновление рабочих таблиц. Прав суперпользователя, создания ролей, изменения схемы и записи в историю миграций у неё нет. Имя владельца базы и ранее созданные пароли сохраняются при обновлении локального Compose.
- Для тестовой выдачи сессий и ручного конца в Local требуется явное включение. Локальный Compose включает обе функции и публикует порты на loopback. В Production эти маршруты отсутствуют. React Router обновлён до 7.18.6, Ajv до 8.20.0.
- Публичный WebSocket ограничивает число активных соединений и частоту новых подключений на реплику. При отказе HTTP GET снимка остаётся доступен.

## Масштабирование и границы кода

- Разные команды могут подавать апелляции параллельно. Совместная блокировка окна взаимоисключается с ручным закрытием, а отдельная блокировка по ключу квоты сохраняет одну подачу на команду и задачу.
- Очередь жюри выдаёт до 50 апелляций за запрос. Курсор учитывает время подачи и ID и привязан к турниру. Работа с курсором проходит через те же серверные проверки прав.
- Results блокирует отдельный результат в начале записи и атомарно обновляет версию турнира перед коммитом. Время обновления строки версии записывается в метрику. Краткие серии уведомлений по одному турниру объединяются до перестроения кэша подписчиков.
- Worker параллельно публикует одно сообщение, читает одно сообщение с другого AMQP-канала и проверяет один отложенный повтор. Outbox, inbox, подтверждение после коммита и карантин сохраняют свои гарантии.
- Кэш зависит от `IStandingsSource`, личные результаты и основание апелляции имеют отдельные порты. Формирование `RecheckRequested` вынесено из сценария ручного выбора в отдельный преобразователь события.

## Проверки

- Прошли 235 backend-тестов, 120 frontend-тестов, 99 тестов контрактов, пять тестов fixtures и четыре проверки HTTP readiness. Проверены TypeScript, production-сборка, соответствие DTO схеме и зависимости проектов. Повторный npm audit сообщил о нуле известных уязвимостей.
- Интеграционные тесты на PostgreSQL и RabbitMQ прошли в изолированных проектах. Checking — 47 и отдельное восстановление назначения в новом процессе, Results — 28, Appeals — 33. Проверка инфраструктуры подтвердила три подключения к своим БД, шесть отказов при подключении к чужим БД, маршрутизацию RabbitMQ и запуск API без root.
- На изолированном `matigr-review-fixes-20261123` готовы все API, базы и RabbitMQ. Через API подтверждены первая апелляция после вердикта старшего, одновременная подача с разными ключами, повтор успешного запроса, назначение перепроверки и закрытие после публикации изменённого результата.
- Три runtime-роли проверены запросами к PostgreSQL. У каждой `rolsuper=false`, отсутствуют права создания ролей и БД, создания объектов в `public` и изменения истории миграций. Повторный запуск всех миграционных контейнеров сохранил опубликованный снимок версии 4 в уже заполненной базе.
- Сто параллельных локальных GET вернули идентичный снимок из 820 байт для трёх команд и двух задач. В этом запуске p50 составил 279 мс, p95 — 364 мс. WebSocket прислал согласованный снимок, условный GET ответил `304`. Размер турнира и среда относятся только к этому прогону.
- Docker build прерван после повторных ошибок загрузки NuGet. Для проверок использованы локально собранные Release-артефакты в Linux-контейнерах и отдельные подсети. Изолированный стенд остановлен с сохранением данных.

## Эксплуатационные ограничения

Общая версия турнира всё ещё обновляется в одной строке, и каждый передаваемый снимок содержит таблицу целиком. Решение о дельтах, пакетной записи и виртуализации зависит от измерений на согласованных размерах турнира, числе зрителей и частоте вердиктов. Совместимость смешанных версий при поэтапном развёртывании требует отдельной проверки.

Локальный Compose использует одиночные PostgreSQL и RabbitMQ с очередями classic. Отказоустойчивость при потере узла, целевой SLO и максимальная нагрузка требуют отдельной среды и критериев. Периоды хранения outbox, inbox и аудита зависят от срока возможной повторной доставки и требований к расследованию. Автоочистка требует согласованной политики, чтобы не снять защиту от повторного применения событий.
