# Matigr — инструкции для Codex

## Проект и этап

Matigr — проверка решений на турнире, результаты команд и апелляции. Три сервиса: **Checking, Results, Appeals**; C# / ASP.NET Core / .NET 10, отдельная PostgreSQL на сервис, RabbitMQ, один frontend React / TypeScript / Vite. Локальная среда — Docker Compose.

На 26 октября 2026 первоначальный MVP завершён: **82/82 задач**, V1–V6 приняты. Спецификации/планы/задачи одобрены 23 октября, реализация поручена отдельно и выполнена. Теперь работа — развитие приложения. Не начинать V0 заново и не переоткрывать завершённые задачи без причины. Production-регистрация/вход и публичный backend не реализованы; production SLO не подтверждён.

## Выполнение изменений

- Пользователь задаёт поведение; агент сам находит влияние на API, сообщения, БД/миграции, frontend, документы и тесты. Не требовать списка файлов.
- Для новой бизнес-функции/правила подготовить соразмерные spec/план/задачи и критерии приёмки. До реализации согласовать неизвестные бизнес-решения и существенное расширение объёма. Принятое повторно не согласовывать; молчание не одобрение.
- Небольшие исправления без изменения бизнес-правил выполнять сразу; отдельные spec/plan/tasks ради формальности не создавать.
- Обновлять затронутые документы и известных потребителей контрактов вместе с реализацией. Внешние DTO/сообщения отделять от внутренних моделей. Сохранять даты одобрений; новые решения отмечать отдельно.
- Приём/загрузка, фото/QR/ручная идентификация, бланки, турнирный CRUD и вопросы исключены из исходного MVP (D24). Новое явное поручение может расширить объём; отразить это в документах, не добавляя соседние процессы самостоятельно.

## Инварианты для реализации и ревью

Полные правила — в спецификациях и D01–D24; сохранять следующие ограничения:

- **Владение:** Checking — Check, вердикт и ссылка на уже принятое решение; Results — баллы/публикация; Appeals — жизненный цикл апелляции. Не дублировать полномочия, не создавать сервис на агрегат/экран. Запрещены чужая БД, межсервисные FK, общие ORM-сущности/бизнес-агрегаты.
- **Назначение:** одна отправка команды на задачу турнира; любое жюри проверяет любую задачу, максимум одна незавершённая проверка, включая апелляционную. Закрытие страницы/потеря связи сохраняют назначение; timeout не освобождает. Ручное освобождение и его полномочия не согласованы.
- **Отказ:** та же проверка идёт в очередь старшего, обычный жюри сразу свободен; занятый старший не мешает постановке в очередь. Его вердикт после такой передачи не обжалуется.
- **Результаты:** неизменная стоимость задачи до турнира; Correct — стоимость, Incorrect — ноль. Сумма по задачам, равные делят место, `1, 1, 2`. Автопубликация после обработки Results, включая коррекции. Общая таблица публична; материалы/действия жюри/апелляции защищены серверными правами.
- **Подача апелляции:** после публикации до ручного конца турнира организатором, без интервала от публикации. Одна на команду/задачу/турнир за весь процесс; закрытие/коррекция не восстанавливают квоту. Подача не назначает перепроверку автоматически.
- **Перепроверка:** жюри выбирает апелляцию вручную и само проверяет (может первоначальный проверяющий), с общим лимитом одной проверки. Отказ — та же перепроверка старшему, отказавшийся свободен; без второго Check/Appeal. Закрытие только после подтверждения опубликованного результата Results, включая no-op. Устаревшая перепроверка не затирает новый результат.
- **Конец/материалы:** принятые вовремя работы/апелляции можно брать и завершать после конца. Локальный адаптер ручного конца не турнирный CRUD/согласованный будущий upstream. Fixtures — уже принятые/идентифицированные решения с неизменяемыми ссылками, не API приёма. Комментарии к вердиктам не нужны; нужны исход, авторство, история.
- **Надёжность:** outbox/inbox, идемпотентность, версии, recovery, аудит; без предположения exactly-once/глобального порядка. Повтор HTTP не новая операция. Отсутствие результата, опубликованный ноль и pending различаются. Frontend не владеет баллами/правами. Не придумывать сроки/лимиты, частичные баллы, ранжирование и повторную подачу.
- **Вход:** тестовые субъекты только Local/Test, production frontend без переключателя. Dev-выдача удостоверений изолирована; замена поставщика должна сохранять внутренние ID/серверные права.

## Проверки

Команды — из корня. Версии заданы файлами окружения/lock-файлами; `scripts/check.ps1` использует `.tools/dotnet/dotnet.exe`, если он есть, иначе системный SDK. Системные версии ради задачи не менять.

| Изменение | Команды |
| --- | --- |
| Документы | `node scripts/check-docs.mjs`, `git diff --check` |
| Границы проектов | `node scripts/check-architecture.mjs` |
| Frontend | `npm run typecheck:web`, `npm run test:web`, `npm run build:web` |
| HTTP/сообщения | `npm run test:contracts`, `npm run check:api` + тесты затронутых производителей/потребителей |
| Полный обычный набор | `./scripts/check.ps1` (`-Restore`, если нужно восстановить зависимости) |
| PostgreSQL/broker | `node scripts/check-checking-storage.mjs`, `node scripts/check-results-storage.mjs`, `node scripts/check-appeals-storage.mjs`: читать сценарий, использовать изолированную среду |

Выбирать проверки по риску; успешный подходящий набор без причины не повторять/расширять. Проверять затронутые инварианты: конкурентное назначение, повтор команды, дубли/перестановку событий, recovery, устаревшую апелляцию. Наличие файлов/сборка не доказывают бизнес-поведение. Исторические 441 тест от 24 октября не подтверждают новую правку; непройденные проверки не выдавать за успешные.

## Git и передача контекста

Приватный [SlnkvDns/matigr](https://github.com/SlnkvDns/matigr), remote `origin`. `codex/implementation-v0` — историческая ветка завершённого MVP, не ограничение текущей стадии. Новую самостоятельную функцию начинать в `codex/<краткое-имя>` от проверенной актуальной базы с учётом поручения и существующих изменений.

Завершённые проверенные шаги фиксировать отдельными коммитами вместе с документацией; перед коммитом проверить diff/статус, не включать чужие правки. Push, публикацию и изменение доступа выполнять по соответствующему явному поручению; прежнее разовое разрешение не постоянно.

При завершении сообщить сделанное, реальные проверки, коммиты, ограничения/остаток. При изменении состояния обновить [progress.md](docs/implementation/progress.md): задача, решения, проверки, остаток, ссылки на подробности. Важные решения не оставлять только в чате или игнорируемом `.local/`.

Устойчивые инструкции — здесь, актуальный итог — progress, бизнес-поведение — specs, доказательства — журнал этапа. [Архив MVP](docs/implementation/progress-mvp-2026-10-24.md) не дописывать/не читать целиком без необходимости. Завершённые этапы архивировать без потери текста/ссылок и изменения прошлых результатов.

Этот корневой AGENTS.md действует для репозитория. Учитывать применимые вложенные AGENTS.md/AGENTS.override.md; не предполагать их автоматическую загрузку из корня. Новому чату нужен актуальный checkout: инструкция не переносит файлы в другую копию проекта.

## Локальные данные и публикация

`npm run dev:web` — `http://127.0.0.1:5173`, proxy API 5101/5102/5103; backend/Compose — по README. Проверять readiness БД/брокера/API и реальные запросы через frontend.

Сохранять volumes, секреты, ключи, бизнес-состояние; токены/ключи не выводить в логи и не публиковать. Перед запуском определить нужный Compose-проект по текущему состоянию/поручению; спросить при неоднозначности. Последний проверенный пользовательский стек — `matigr-e2e-final`: турнир завершён, работы/апелляции завершены, новые апелляции закрыты. Не сбрасывать окно/квоты/назначения ради демонстрации.

Сквозные/fault scripts меняют данные/останавливают сервисы: читать заранее, запускать на явно выбранном изолированном тестовом проекте. Без отдельного поручения не удалять volumes, не делать factory reset, не заменять ключи. При потере Linux-движка разрешены перезапуск Docker Desktop и сохранение только временного `C:\Users\Denis\AppData\Local\Docker\run` под резервным именем; не удаление данных.

Sites — отдельный приватный интерфейс без backend/production-входа. Обновлять существующий Site по [sites-hosting.md](docs/implementation/sites-hosting.md); `/sites/` исключён из основного Git. Не заменять API имитацией ответов. Публичный backend, production-аутентификация и изменение аудитории требуют новой задачи.
