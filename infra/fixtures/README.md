# Подготовленные данные V0

`manifest.json` — общий неизменяемый набор v1: один турнир, три команды, две задачи (10/20 целых баллов), два обычных жюри, один старший и организатор. Scope субъектов явный. UUID стабильны; `testSubjectId` служит только ключом выбора серверного dev-профиля. Манифест не выдаёт полномочий браузеру сам по себе.

В `solutions` уже принятые идентифицированные ссылки на готовые текстовые материалы. `materialRef` разрешается только по allowlist манифеста. Файлы, SHA-256 и версии фиксированы, в контейнер Checking монтируются read-only. Материал не публикуется статическим web-сервером. Это не имитация приёма, QR или загрузки.

```sh
node scripts/init-local.mjs
node scripts/prepare-fixtures.mjs
node --test tests/fixtures/fixtures.test.mjs
```

Повтор подготовки проверяет контрольные суммы и сохраняет прежние секреты. Изменение материала/стоимости не должно обновлять уже загруженные данные турнира. В CHK-BE-03 реализован внутренний bootstrap в собственной БД Checking: при Local startup после миграций одна транзакция закрепляет checksum/версию набора, reviewer scopes и шесть SolutionReference/Initial Check с локальной историей. Повтор не меняет назначение/вердикт, конфликт снимка или manifest останавливает импорт. Bootstrap не публикует факты приёма/загрузки. Seed Results — RES-BE-02; окно Appeals создаётся в APL-INF-01 через insert-if-absent и не открывает Closed. Checking не записывает manifest в чужие БД.

Read-only adapter разрешает только полный снимок решения из allowlist. Пути/URL из запроса не открываются; ссылки filesystem отвергаются, SHA-256 проверяется при каждом чтении, наружу возвращается только неизменяемая копия проверенных байтов. Отсутствие файла/нарушение целостности — ошибка материала, без Incorrect или изменения Check. HTTP-права актуального владельца подключаются в CHK-BE-05/06; нового endpoint приёма или bootstrap нет.

Секреты находятся в игнорируемом `.local/secrets/`, вне Git; резервная копия требуется вместе с volumes. Приватный RSA-ключ issuer монтируется только dev-адаптеру Checking; Results/Appeals позднее получают только публичный ключ. В CHK-BE-04 реализована [выдача/profile и проверка удостоверений](../../contracts/authentication.md), включённая только в Local/Test. `capability-protection-key` используется для защиты восстанавливаемого capability и чувствительных HTTP receipts (CHK-BE-02). Сама команда подготовки не выдаёт токенов и не реализует регистрацию. При потере одного ключа пары операция завершается ошибкой вместо незаметной смены идентичности.
