# Подготовленные данные V0

`manifest.json` — общий неизменяемый набор v1: один турнир, три команды, две задачи (10/20 целых баллов), два обычных жюри, один старший и организатор. Scope субъектов явный. UUID стабильны; `testSubjectId` служит только ключом выбора серверного dev-профиля. Манифест не выдаёт полномочий браузеру сам по себе.

В `solutions` уже принятые идентифицированные ссылки на готовые текстовые материалы. `materialRef` разрешается только по allowlist манифеста. Файлы, SHA-256 и версии фиксированы, в контейнер Checking монтируются read-only. Материал не публикуется статическим web-сервером. Это не имитация приёма, QR или загрузки.

```sh
node scripts/init-local.mjs
node scripts/prepare-fixtures.mjs
node --test tests/fixtures/fixtures.test.mjs
```

Повтор подготовки проверяет контрольные суммы и сохраняет прежние секреты. Изменение материала/стоимости не должно обновлять уже загруженные данные турнира. Внутренний bootstrap в БД Checking реализуется в CHK-BE-03; seed Results — RES-BE-02; окно Appeals создаётся в APL-INF-01 через insert-if-absent и не открывает Closed. На этом этапе manifest не записывается напрямую в чужие БД.

Секреты находятся в игнорируемом `.local/secrets/`, вне Git; резервная копия требуется вместе с volumes. Приватный RSA-ключ issuer монтируется только dev-адаптеру Checking; Results/Appeals позднее получают только публичный ключ. В CHK-BE-04 реализована [выдача/profile и проверка удостоверений](../../contracts/authentication.md), включённая только в Local/Test. `capability-protection-key` сохраняется для последующей защиты восстанавливаемого capability. Сама команда подготовки не выдаёт токенов и не реализует регистрацию. При потере одного ключа пары операция завершается ошибкой вместо незаметной смены идентичности.
